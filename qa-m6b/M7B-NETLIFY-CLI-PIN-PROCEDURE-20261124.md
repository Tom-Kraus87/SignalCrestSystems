# M7B — Netlify CLI 26.2.0 Project-Local Pin Procedure

**Date:** 2026-11-24  
**Status:** **PREPARE ONLY — DO NOT install yet**  
**G0 finding:** Netlify CLI **26.2.0** was present globally but **unpinned** for this project  
**Production:** HOLD  

## Goal

Pin **exactly** `netlify-cli@26.2.0` as a **project-local** devDependency so future authorized deploys do not silently drift to another CLI major/minor.

## Prepared pin artifact

File: `tools/netlify-cli-pin/package.json`

```json
{
  "name": "scs-netlify-cli-pin",
  "private": true,
  "description": "Project-local Netlify CLI pin. Install only after Owner authorization.",
  "engines": { "node": ">=18" },
  "devDependencies": {
    "netlify-cli": "26.2.0"
  }
}
```

Exact version string: **`26.2.0`** (no `^` / `~` range).

## Install procedure (AUTHORIZED LATER — not this pass)

When Owner separately authorizes network install:

```powershell
cd "tools\netlify-cli-pin"
npm install --package-lock-only
npm ci
npx netlify --version
```

Acceptance:

- `npx netlify --version` reports **26.2.0**  
- `package-lock.json` is committed only after integrity hashes are generated by npm (do not invent lockfile hashes)  
- Deploy commands use `npx --prefix tools/netlify-cli-pin netlify …` (or equivalent) rather than an unpinned global binary  

## Forbidden this pass

- **DO NOT run `npm install`**  
- **DO NOT run `npm ci`**  
- **DO NOT deploy**  
- **DO NOT** mutate production Netlify site settings  

## Global CLI note

A global `netlify` 26.2.0 may exist on the workstation. It is **not** a project pin. Do not treat global presence as release control until this local pin is installed and verified under separate authorization.
